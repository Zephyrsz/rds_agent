  ↓

  ├─ 是 → 立即实施 Filter 对象化（P1）
  └─ 否 → 继续
       ↓

  ├─ 是 → 立即实施 Measure/Metric 分离（P1）
  └─ 否 → 继续
       ↓
是否需要量化系统准确率？
  ├─ 是 → 立即实施 Benchmark（P1）
  └─ 否 → 继续
       ↓
P1 完成后，进入 P2
  ↓
是否有数据膨胀或聚合错误？
  ├─ 是 → 优先实施 Entity + Relationship（P2）
  └─ 否 → 继续
       ↓
是否需要企业级部署？
  ├─ 是 → 优先实施 Policy Engine（P2）
  └─ 否 → 继续

  ├─ 是 → 优先实施 Trusted Assets（P2）
  └─ 否 → 继续
       ↓
是否有大量同比环比需求？
  ├─ 是 → 实施时间智能（P2）

## 结论

**立即行动的 3 个理由：**

1. **P1 投入小、见效快**（3.5 周，30 人天）
2. **当前 30% 覆盖度已经是瓶颈**（无法支持企业级部署）
3. **延迟成本高**（配置债务累积，后续重构更困难）

**首选路径：标准演进路径（12 周）**
- 覆盖度从 30% → 75%
- 投入约 200 人天
- ROI 极高的 P1+P2 核心功能

**关键成功因素：**
- ✅ 获得数据架构师支持（P2 阶段必须）
- ✅ 保持向后兼容（渐进式迁移）
- ✅ 持续 Benchmark（每次变更都回归测试）
- ✅ 从简单场景开始（不要一次性重构所有配置）
